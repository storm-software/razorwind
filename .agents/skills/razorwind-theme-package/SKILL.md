# Razorwind Theme Package

Scaffold a new `@razorwind/<target>` plugin that turns extracted DTCG tokens into theme files for a specific application.

**Canonical references** (copy structure from these, adapt types/renderers):

- `packages/shiki/` — JSON theme files only (simpler baseline)
- `packages/vsce/` — theme files + packaging artifacts (extension, scripts, README)

## When to use

- User asks for a new Razorwind package that **outputs a theme** for an app/tool
- Target is syntax highlighting, editor chrome, terminal colors, etc.
- Not for CSS/Tailwind/token-export packages (`css`, `tailwindcss`, `style-dictionary`, …)

## Non-negotiables

1. **`mapTheme` is required** — user maps `Tokens | Record<string, Tokens>` → target theme shape(s)
2. **Generate `INSTALL.md`** in the output directory — brief steps to wire the generated theme into the target app
3. **Default export is a `definePlugin`** with `generate` calling the package generator
4. **Export helpers** consumers need in `mapTheme`: at least `flattenTokens` (and `resolveTokenSets` when useful)

## Package layout

```
packages/<name>/
├── package.json              # @razorwind/<name>
├── project.json              # Nx project, tags: ["platform:node"]
├── powerlines.config.ts
├── vitest.config.mts
├── tsconfig.json
├── tsconfig.lib.json
├── tsconfig.spec.json
├── README.md                 # package docs (how to use the plugin)
├── src/
│   ├── index.ts              # definePlugin + re-exports
│   ├── types.ts              # FlatToken, Theme type, mapTheme type, PluginOptions
│   ├── flatten.ts            # flattenTokens + resolveTokenSets
│   ├── format.ts             # re-export formatTokenValue, toCssVar from @razorwind/core/utils
│   ├── generate.ts           # normalizeThemes, render*, generate*
│   └── install.ts            # optional: renderInstallMd (keep generate.ts thin)
└── tests/
    └── generator.test.ts
```

Start from **shiki** when the target is “emit theme JSON/files”. Use **vsce** patterns only when you also need packaging manifests/scripts.

## Core API shape

### Options

```ts
export interface <Name>PluginOptions {
  /** Output dir relative to cwd. @defaultValue `"<name>-themes"` */
  outputPath?: string;

  /** Required — maps extracted tokens to theme document(s). */
  mapTheme: Generate<Name>Theme;

  /** Optional filter for flattenTokens helper only — does not filter mapTheme input. */
  includeTypes?: TokenType[];
}
```

### `mapTheme`

```ts
export type Generate<Name>Theme = (
  tokens: Tokens | Record<string, Tokens>
) => Theme | Theme[] | Record<string, Theme>;
```

- Accept single theme, array, or record (key fills missing `name` when needed)
- Validate with `normalizeThemes` — throw clear `@razorwind/<name> mapTheme()…` TypeErrors
- Empty result after normalize → throw

### Plugin entry

```ts
export default definePlugin((options?: <Name>PluginOptions) => ({
  name: "<name>",
  generate: async spec => {
    if (!options) {
      throw new Error("@razorwind/<name> requires options: { mapTheme }");
    }
    return generate<Name>Theme(spec, options);
  }
}));
```

Use `createDocument` from `@razorwind/core/utils` for every emitted file. Plugin meta name: `razorwind-<name>`.

## Generator responsibilities

In `generate.ts`:

1. `assertOptions` — require `mapTheme` (plus any target-specific required fields)
2. `themes = normalizeThemes(options.mapTheme(spec.tokens))`
3. Emit theme artifact(s) under `outputPath` (slugify theme `name` for filenames; avoid collisions)
4. Emit **`INSTALL.md`** at `join(outputPath, "INSTALL.md")`

Do **not** put long install prose in the package README only — consumers of *generated* themes need `INSTALL.md` beside the output.

### `INSTALL.md` requirements

Keep it short. Cover only configuration of the **generated** theme in the target app:

- What files were generated (names/paths)
- Minimal install / register / load steps for that app
- One concrete code or config snippet when the app needs it
- Theme labels/ids the user must select or pass

Optional override: `options.installGuide?: string` — if set, write that body instead of the default template (same pattern as vsce’s `readme`).

Template sketch:

```markdown
# Installing <Theme Display Name>

Generated by `@razorwind/<name>`.

## Files

- `themes/<slug>.json` — …

## Setup

1. …
2. …

## Select / load theme

…
```

Implement as `renderInstallMd(themes, options)` so tests can assert content without running the full plugin.

## Shared helpers (copy from shiki/vsce)

| File | Role |
|------|------|
| `flatten.ts` | Walk DTCG trees → `FlatToken[]`; split multi-theme records via `THEME_BASENAME_PATTERN` |
| `format.ts` | `export { formatTokenValue, toCssVar } from "@razorwind/core/utils"` |
| `types.ts` | `FlatToken` with `path`, `type?`, `value`, `cssValue`, `description?`, `theme?` |

`flattenTokens` is for **author convenience inside `mapTheme`**. Always pass full `spec.tokens` into `mapTheme` unfiltered.

## Workspace wiring

After creating the package:

1. Add `packages/<name>` reference in root `tsconfig.json`
2. Add `"@razorwind/<name>": workspace:*` under the catalog / workspace package list in `pnpm-workspace.yaml` (match how `vsce` / `shiki` are listed)
3. Run `pnpm install` so the workspace link resolves
4. Mirror `package.json` / `powerlines.config.ts` / vitest aliases from `packages/shiki`

## Tests (minimum)

Mirror `packages/shiki/tests/generator.test.ts`:

- `flattenTokens` / `resolveTokenSets`
- `normalizeThemes` (single / array / record + invalid)
- `generate*` writes expected theme paths
- **`INSTALL.md` is emitted** and mentions theme name(s) / setup steps
- Default plugin export `generate` with `mapTheme` integration
- Missing `mapTheme` throws

## Anti-patterns

- Hardcoding a full theme without `mapTheme` — the mapping **is** the product API
- Filtering tokens before calling `mapTheme`
- Skipping `INSTALL.md` because the package README already explains the plugin
- Inventing theme JSON fields — match the target app’s documented theme schema
- Duplicating large formatters — reuse `@razorwind/core/utils`
